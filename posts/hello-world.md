很久没有认真写点东西了。

平时的工作大多是修 bug、调参数、看日志，问题解决完就过去了，脑子里留下的只有模糊的印象。等过几个月再遇到类似的情况，往往又要从头查一遍。所以决定还是把过程记下来——**写给自己看**，顺便也许能帮到别人。

## 为什么是静态站点

这个博客没有数据库，没有后端服务，甚至连构建框架都没用。文章是普通的 Markdown 文件，构建脚本把它们渲染成 HTML，然后交给 GitHub Pages 托管。

这么选的原因很简单：

- 写作和发布之间没有中间层，打开编辑器就能写
- 没有运行时依赖，也就不存在「哪天服务挂了」这种事
- 整个站点的源代码都在自己手里，想改什么改什么

## 技术上的取舍

构建脚本只有几百行，做的事情也很直白：读 Markdown、套模板、写文件。

```js
const posts = all
  .filter((p) => !p.draft)
  .sort((a, b) => b.date - a.date);
```

排序按时间倒序，草稿直接跳过。没有插件系统，没有配置文件层层覆盖，想要什么行为就改对应那几行。

> 简单不是功能少，而是每一处复杂都有明确的理由。

## 关于字体

中文网页字体一直是个麻烦事：一个完整的中文字体动辄十几 MB，直接加载会让人等很久。

这里的做法是用按 `unicode-range` 切好的字体分片。浏览器只会下载页面实际用到的那几片，通常只有几十 KB。代价是首次加载时字体文件比较零碎，但换来的是整体体积可控。
